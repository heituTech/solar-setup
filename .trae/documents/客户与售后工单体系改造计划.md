# 客户与售后工单体系改造计划

## Context

当前系统（Egg 微服务 + Vue3/Element Plus）在客户录入、角色权限、售后工单和项目展示上存在问题：

- 新建客户时地区是手写输入，容易产生不一致；来源/客户类型字段实际由订单阶段决定，客户阶段无意义。
- 客户没有记录创建人/创建时间，也没有所属销售人员的变更审计。
- 缺少“售后经理”角色；工程师类角色在菜单和 API 层仍能接触销售类页面。
- 工单创建不强制绑定订单，没有记录创建人姓名、订单号，也没有干系人概念；创建后无通知。
- “项目与设备”是独立页面，但项目/设备与订单实际是一对一关系，应合并进订单详情。

目标：客户地区改为柬埔寨省份下拉（贡布+白马合并为一项）；客户记录创建人与所属销售并可审计；新增售后经理角色与严格页面权限；工单强制绑定订单、记录创建信息、维护干系人并通知售后经理；删除独立项目页，项目/设备详情内嵌订单详情。

## 验证

1. 运行迁移（按需，需可达数据库）：`npm run migrate:identity`、`npm run migrate:sales`、`npm run migrate:delivery`。
2. 前端构建：`npm run build --workspace @solar/web`，确认无编译错误。
3. 后端单测：`npm test --workspaces --if-present`（已有 56 个 sales 用例）。
4. 手动/接口验证要点：
   - 用超管创建客户 → 地区只能选省份，创建人/时间为当前用户；`customer_owner_logs` 在经理改归属后新增记录。
   - 销售员登录：看不到客户归属修改入口，直接 PATCH owner 返回 403。
   - 电气/结构工程师、售后经理：菜单只有勘测、订单、售后工单；访问 customers/quotes/catalog 被重定向首页，直接调 API 返回 403；订单详情无金额字段；可见项目/设备/时间线。
   - 工单创建必须选订单；`tickets` 有 `created_by_name/order_no`；`ticket_stakeholders` 默认含超管 + 售后经理 + 订单项目工程师；售后经理收到系统通知（邮件配置有效时同时发邮件），可在详情调整干系人。
   - 订单创建后所属销售收到系统通知。
   - 访问 `/workbench/projects` 已不存在；“项目与设备”内容在订单详情可见。
