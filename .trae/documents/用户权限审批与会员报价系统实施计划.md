# 用户权限、审批与会员报价系统实施计划

## Context

当前系统只有「管理员密码 + 公开商品接口」，任何人都能直接增删改商品，也没有销售组织、审批、会员注册和访客/会员差异化报价。本次改造需要建立完整角色体系（超级管理员、销售经理、销售人员、会员、访客），把商品变更纳入审批流，并新增基于商品组合的报价区间、精确报价、安装费和 PBP 回本周期。

已确认的产品决策：

- 电价同时支持 USD/kWh 与 KHR/kWh，按系统汇率换算。
- PBP 同时给出两种口径：按日用电量节省、按光伏预计发电量节省。
- 销售人员的新增/修改/删除商品全部需要销售经理审批；经理和超管直接生效。
- 邮件发送先进入开发模式（验证码打印到服务端日志），SMTP 配置就绪后切换真实发送。
- 员工账号由有权限的管理者直接设置初始密码，审批通过后账号生效；不额外引入邮件激活流程。
- 实施阶段先创建临时超管 `admin / admin123` 用于联调，验证完成后由你改用 SQL 设置正式账号。

## 2. 认证与权限

新增依赖：`jsonwebtoken`、`bcryptjs`、`nodemailer`。

- `POST /api/auth/login`：identifier（username 或 email）+ password → JWT（HS256，7 天）+ 用户信息。
- `POST /api/auth/request-code`：会员注册验证码；60 秒冷却、10 分钟有效、同邮箱/IP 限频。
- `POST /api/auth/register`：email + code + password + phone + project_address + electricity_price/currency，验证通过后创建 member 并返回 JWT。
- `GET /api/auth/me`、`PATCH /api/auth/me`（会员修改手机号、地址、电价）。
- `GET /api/auth/logout` 可省略，前端清除 token。

`server/middleware/auth.js`：

- `requireAuth`：验签后查库，确认账号存在、`status='active'`、角色与 token 一致。
- `optionalAuth`：用于报价接口识别会员。
- `requireRole(...roles)`。
- `requireManagerOf(userId)`：经理只能操作 manager_id 指向自己的销售人员。

密码统一 bcrypt（cost 10），邮箱/用户名 trim + 小写化。JWT 密钥放 `.env`。

## 3. 账号管理

- 超管：`GET/POST/PUT/DELETE /api/admin/users`
  - 可创建/修改/删除 sales_manager、salesperson；不提供创建 super_admin。
  - 创建时直接设置密码；修改可重置密码、启停账号、调整所属经理。
  - 禁止删除最后一个超管、禁止删除自己；删除经理前必须先转移其下属或先删除/转移下属；删除销售人员时取消其 pending 商品申请。
- 经理：`GET /api/admin/users/subordinates`（查询下属，无需审批）。
  - `POST/PUT/DELETE /api/admin/users/subordinates` 不直接改库，而是创建 `account_*` 审批请求，`approver_role='super_admin'`。
  - payload 包含 username/email/phone/manager_id/password_hash，manager_id 固定为当前经理。
- 审批通过后账号才创建/变更/删除；被拒绝则不做任何修改。

## 4. 商品权限与审批

商品读写拆分：

- `GET /api/products/:category`：公开，仅 `sales_status='on_sale'`，返回报价所需字段。
- `GET /api/products/admin/:category?status=all|on_sale|discontinued`：salesperson 及以上，含停售。
- `POST/PUT/DELETE /api/products/:category[/:id]`：需登录。
  - super_admin、sales_manager：直接写，返回 `{ok:true}`。
  - salesperson：校验字段后创建 `product_*` 审批请求，返回 `202 {approval_id,status:'pending'}`；审批前数据不变。

`server/routes/products.js` 把创建/更新/删除逻辑抽成内部函数，直写和审批通过复用同一套字段白名单与校验。

`GET /api/config` 只返回公开键；`PUT /api/config` 需 super_admin 或 sales_manager；移除 `/api/config/auth`。

## 5. 审批中心

- `POST /api/approvals`：服务端根据角色/target 决定审批人；同一 target 已有任意 pending 时返回 409（避免修改与删除请求交叉）。
- `GET /api/approvals?scope=mine|to_review|all`：
  - 超管：所有账号类申请 + all（也可审批任何 pending 商品申请）。
  - 经理：自己下属的商品类申请 + 自己提交的账号申请。
  - 销售：自己提交的申请。
- `POST /api/approvals/:id/approve|reject|cancel`：
  - 仅 pending 可流转。
  - approve 使用事务 + `SELECT ... FOR UPDATE`，执行实际 SQL 后再更新状态，防止重复审批双写。
  - reject 必须填写 `review_note`。
  - 经理不能审批自己的请求；销售不能审批；超管可审账号类请求。
- 前端审批徽章：pending / approved / rejected / cancelled。

## 6. 报价引擎

新增 `server/services/pricing.js`，新增 `POST /api/quote`，保留 `/api/recommend` 兼容。

### 输入

`load_power, daily_hours, autonomy_days, battery_type?, system_voltage?, peak_sun_hours?, inverter_id?, battery_id?, panel_id?, include_installation, electricity_price?, price_currency?`

### 需求计算（沿用现有逻辑）

- 日用电量 `dailyKwh = load_power * daily_hours / 1000`
- 逆变器需求 `load_power * 1.25`
- 电池需求 `dailyKwh * autonomy_days / (DOD * 0.92)`，DOD 按电池类型 0.5/0.8/0.9
- 光伏需求 `dailyKwh / (peak_sun_hours * 0.85 * 0.95)`

### 候选与组合

- 仅取 `sales_status='on_sale'`。
- 逆变器按功率/电压过滤；电池按类型/电压匹配（无匹配时放宽）；面板全量。
- 组合内要求逆变器 `battery_voltage` 与电池 `nominal_voltage` 匹配；会员已选逆变器时，电池候选必须与其电压一致，否则 400。
- 每个电池型号数量 `ceil(needKwh / capacity)`，每个面板型号数量 `ceil(needKwp / rated_power)`，设置上限（电池 50、面板 200）。
- 枚举「逆变器 × 电池型号 × 面板型号」，上限 10,000 组合；超限则降级为分类极值估算并标记 `truncated`。
- 每个组合计算硬件小计、安装费、总价；安装费 `max(500, 20% × 硬件小计)`，比例和下限来自 system_config。
- 输出 `price_range{min_usd,max_usd,min_khr,max_khr}`、`min_combo`、`max_combo`、`combo_count`、`is_exact`。
- 任一类别无可行候选时返回 `400 { error:'no_feasible_combination', category }`，前端提示调整需求或联系销售。

### 访客 / 会员门控

- 访客：只返回区间、安装费、组合数，不返回商品明细和精确价，附 `requires_registration:true`。
- 会员：未选商品返回同区间；选 1-2 类后区间收窄；逆变器+电池+面板全部指定时 `is_exact=true`，返回确定总价。
- 传了 id 但商品停售/不可行 → 400。

### 安装费

- 单独返回 `hardware_usd`、`installation_usd`、`total_usd` 及 KHR 对应值。
- 访客与会员区间均包含安装费。

### PBP（会员填写电价时）

- 电价先按币种换算为 USD/kWh：`usd_per_kwh = price / usd_to_khr`（KHR 时）。
- 口径 A：`annual_savings_consumption = dailyKwh * 365 * usd_per_kwh`
- 口径 B：`annual_savings_generation = panelKwp * peak_sun_hours * 365 * 0.8 * usd_per_kwh`
- `payback_years = total_usd / annual_savings`，两种口径分别输出，并同时给 USD/KHR 展示值。
- 区间报价给出 min/max 组合对应的 PBP 区间；精确报价给出确定值。
- 无电价时返回 `pbp_unavailable_reason`；电价为 0 或负数时不计算 PBP。

## 8. 邮件与阿里企业邮箱

`server/services/mailer.js`：

- `MAIL_DEV_MODE=true` 时只打印验证码到服务端日志，不实际发信。
- 生产使用 `nodemailer`，SMTP 配置从 `.env` 读取。

阿里企业邮箱 `public@heitu.tech` 配置步骤：

1. 登录 qiye.aliyun.com，确认 `public@heitu.tech` 账号存在。
2. 域名管理确认 `heitu.tech` 已验证，MX、SPF（`include:spf.qiye.aliyun.com`）配置正确。
3. 邮箱管理 → 安全设置 → 开启「SMTP 服务 / 客户端授权」，生成授权码（只显示一次）。
4. 在 `.env` 配置：

```env
SMTP_HOST=smtp.qiye.aliyun.com
SMTP_PORT=465
SMTP_SECURE=true
SMTP_USER=public@heitu.tech
SMTP_PASS=<授权码>
MAIL_FROM="Solar Setup <public@heitu.tech>"
MAIL_DEV_MODE=false
```

5. 服务器放行 465 出站；若不通改用 587 STARTTLS。上线后检查 SPF/DKIM 与退信。

## 9. 安全与边界

- 密码、JWT 密钥、SMTP 授权码只放 `.env`，不写日志、不返回前端。
- 所有 SQL 参数化；动态 UPDATE 字段白名单。
- 审批 payload 大小限制；账号密码只在 payload 存 hash，审批列表返回前剔除 `password_hash`。
- 登录失败统一提示；验证码限频、限次、一次性。
- 会员不可访问管理接口；经理不能审批自己的请求；销售不能查看他人申请。
- 停售商品不可被会员选中或进入报价。
- 金额统一 Number + 两位小数；KHR 展示取整。
- 删除商品前检查 pending 审批冲突。
